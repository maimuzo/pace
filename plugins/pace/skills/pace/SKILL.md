# PACE

引数: `$ARGUMENTS`

叩く前に、下のコマンドのパスを見てください。パスが絶対パスになっておらず、ドル記号と波括弧で囲んだ変数の形のまま残っているときは、叩かずに止まり、パスが置き換わっていなかったことを利用者に伝えてください。pace.py をほかの経路で探して叩かないでください。

## プランのパス

- 引数のうち `--no-ask` を除いた残りが、プランのパスです（`--no-ask` はいまの版では何も変えません。見せ方は後の版で決めます）。
- プランのパスが無ければ、叩かずに「プランのパスを渡してください（`/pace:pace <プランのパス>`）」と伝えて止まります。
- 下のコマンドでは、プランのパスを単一引用符で囲みます（空白を含むパスを割らないため）。引用符の中では `~` が展開されないので、パスが `~/` で始まるときは、ホームディレクトリの絶対パスに置き換えてから囲みます。パスに単一引用符が含まれるときは、叩かずにその旨を伝えて止まります。

## 手順

1. 次を1回叩きます。

   ```bash
   python3 "${CLAUDE_PLUGIN_ROOT}/scripts/pace.py" init '<プランのパス>'
   ```

   - 0 以外で終わったら、標準エラーをそのまま見せて止まります。
   - `PACE-STATUS: errors=1` が出たら、次へ進まずに、`PACE-STATUS` と `NEXT` の2行を見せて止まります（プランを読めなかった、ということです）。

2. 次を叩きます。

   ```bash
   python3 "${CLAUDE_PLUGIN_ROOT}/scripts/pace.py" next '<プランのパス>'
   ```

   - 0 以外で終わったら、標準エラーをそのまま見せて止まります。
   - `DONE` で始まる行が出たら、その行を見せて止まります（決定と前提の数、失敗したジョブの数です。決定ごとの根拠付けまで終わっています）。

3. `next` の出力は、束ごとに `BUNDLE <束の ID> <agent>` の行と、そのあとに続く `JOB <ジョブファイルの絶対パス>` の行です（`JOB ` のあとの行の残り全部が1つのパスです）。束ごとに Agent を1回呼びます。
   - `subagent_type` は、`BUNDLE` の行の agent（`pace:pace-worker` か `pace:pace-judge`）にします。model は渡しません。
   - 渡す文は、次の1行と、その束の `JOB` のパスを1行に1つずつ並べたものだけにします。

     ```text
     次のジョブファイルを、書いてある順に1件ずつ処理してください。
     ```

   - 1つの出力に並んだ束は、全部を1つのメッセージで並列に呼びます。

4. その出力の全部の束の結果が返るまで待ちます。バックグラウンドで返ったときは、全部の完了の知らせが届くまで、次へ進みません。
   - エラーで返った束（レート制限など、答えを書く前に止まったもの）があったら、`next` を打たずに、そのエラーを見せて止まります。

5. 2へ戻ります。

## 決まり

- 束は必ず subagent に渡し、全部の結果が返ってから次の `next` を打ちます。答えのファイル（`*.out.json`）を自分で書いたり直したりしません。答えの無いジョブは、`next` が差し戻しの1回に数えます。
- `next` の出力に無いファイル（作業ディレクトリの中のほかのジョブや答え）を開きません。
- 輪を断つ・結合（maimuzo/pace#6）と、周の回し方（`report`・`show`・`shown`、直すものと人間に訊くものの返し方。maimuzo/pace#7）は後の版で書きます。いまの版は、根拠付けまで終えた `DONE` で止まります。
