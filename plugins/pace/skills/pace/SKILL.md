# PACE

引数: `$ARGUMENTS`

叩く前に、下のコマンドのパスを見てください。パスが絶対パスになっておらず、ドル記号と波括弧で囲んだ変数の形のまま残っているときは、叩かずに止まり、パスが置き換わっていなかったことを利用者に伝えてください。pace.py をほかの経路で探して叩かないでください。

## プランのパスと起動の形

- 引数のうち `--no-ask` を除いた残りが、プランのパスです。`--no-ask` があれば、最後に人間へ見せずに、呼び出し側へ返します（手順7）。
- プランのパスが無ければ、叩かずに「プランのパスを渡してください（`/pace:pace <プランのパス>`）」と伝えて止まります。
- 下のコマンドでは、プランのパスを単一引用符で囲みます（空白を含むパスを割らないため）。引用符の中では `~` が展開されないので、パスが `~/` で始まるときは、ホームディレクトリの絶対パスに置き換えてから囲みます。パスに単一引用符が含まれるときは、叩かずにその旨を伝えて止まります。
- どの手順でも pace.py が 0 以外で終わったら、既定の起動では標準エラーをそのまま見せて止まります。`--no-ask` では、`PACE-EXIT <コマンド名> <終了状態>` の行と標準エラーの全文を返して止まります（標準エラーには絶対パスが入りうるので、公開の場に写すときは伏せるよう1行添えます）。

## 手順

0. この会話に、前の起動で見せた `show.md` への人間の回答があれば、決まり1の (c) のとおり、質問の文と人間の原文を組にしてプランへ書き、違うと言われた事実を消すか直してから 1 へ進みます。回答が無ければ、そのまま 1 へ進みます。

1. 次を叩きます。

   ```bash
   python3 "${CLAUDE_PLUGIN_ROOT}/scripts/pace.py" init '<プランのパス>'
   ```

   - `PACE-STATUS: errors=1` が出たら（プランを読めなかった）、`next` を打たずに 6 へ進みます。

2. 次を叩きます。

   ```bash
   python3 "${CLAUDE_PLUGIN_ROOT}/scripts/pace.py" next '<プランのパス>'
   ```

   - `DONE` で始まる行が出たら、止まらずに 3 へ進みます。
   - そのほかの出力は、束ごとに `BUNDLE <束の ID> <agent>` の行と、そのあとに続く `JOB <ジョブファイルの絶対パス>` の行です（`JOB ` のあとの行の残り全部が1つのパスです）。束ごとに Agent を1回呼びます。
     - `subagent_type` は、`BUNDLE` の行の agent（`pace:pace-worker` か `pace:pace-judge`）にします。model は渡しません。
     - 渡す文は、次の1行と、その束の `JOB` のパスを1行に1つずつ並べたものだけにします。

       ```text
       次のジョブファイルを、書いてある順に1件ずつ処理してください。
       ```

     - 1つの出力に並んだ束は、全部を1つのメッセージで並列に呼びます。
   - その出力の全部の束の結果が返るまで待ちます。バックグラウンドで返ったときは、全部の完了の知らせが届くまで、次へ進みません。エラーで返った束（レート制限など、答えを書く前に止まったもの）があったら、`next` を打たずに、そのエラーを見せて止まります。
   - 2 を繰り返します。

3. 次を叩きます。

   ```bash
   python3 "${CLAUDE_PLUGIN_ROOT}/scripts/pace.py" report '<プランのパス>'
   ```

   最後の2行が `PACE-STATUS` と `NEXT` です。その前の `FILE fixes` の行が、書き手が直すもの（fixes.md）のパスです。

4. `NEXT: continue` なら、`FILE fixes` の fixes.md を Read し、決まり1と2に沿って直せるものをプランへ直してから 1 へ戻ります。直せるものが1つも無ければ、プランを変えずに 1 へ戻ります（pace.py が、周を続けるか止めるかを決めます）。

5. `NEXT: show` なら 6 へ進みます。ここから先、この起動の中ではプランを直しません（決まり4）。

6. 次を叩きます。

   ```bash
   python3 "${CLAUDE_PLUGIN_ROOT}/scripts/pace.py" show '<プランのパス>'
   ```

   - 出力は、`FILE show <show.md の絶対パス>`・`PACE-STATUS` の行・（プランを読めたときだけ）`SNAPSHOT <写しの sha256>` です。
   - show.md の境目の行（`---- ここから下は書き手の注記で、pace.py は書いていない ----`）より後ろに、注記を足してよいです。足すのは、残った fixes を書かずに残した理由と、その fixes について人間に決めてほしい問いだけです。pace.py の質問と同じことを訊くときは、新しく書かずに「質問1と同じ」と番号で指します。

7. 見せるか返すか。
   - 既定の起動: まず show.md の全文をチャットの返答として書き出します。書き出し終えてから、`SNAPSHOT` の行があれば、次を打って止まります（全文を書き出す前に `shown` を打たないでください。決まり5）。

     ```bash
     python3 "${CLAUDE_PLUGIN_ROOT}/scripts/pace.py" shown '<プランのパス>' '<SNAPSHOT の sha256>'
     ```

   - `--no-ask`: 見せずに、次の3行を返して止まります（`shown` は打ちません。呼び出し側が、show.md を写したあとに `SHOWN-COMMAND` を打ちます）。`SNAPSHOT` の行が無ければ、3行目は `SHOWN-COMMAND none` です。

     ```text
     <show が出した PACE-STATUS の行>
     SHOW <show.md の絶対パス>
     SHOWN-COMMAND python3 "<pace.py の絶対パス>" shown '<プランのパス>' <SNAPSHOT の sha256>
     ```

## 決まり

1. 書き手がプランに足してよい文は、次の3種類だけです。
   - (a) 確かめた事実。出どころは、読み手が辿れる形にします（リポジトリの中の相対パスと行、URL、叩いたコマンドそのものとその出力の要点）。
   - (b) 設計そのものの変更（何を作るか・どう作るか）。
   - (c) 人間の回答。質問の文と人間の原文を組にして書きます（例「読み直しに失敗したときに何を重視するかについて、オーナーは『安全側を重視する』と答えた」）。

   価値や要求の理由が要る fixes と、確かめられない事実は、書かずに注記で人間に訊きます。
2. 秘密・個人の絶対パス・公開してよいか分からない中身は、プランにも注記にも書きません。そういう出どころしかない事実は書かずに、「出どころを伏せた」と添えて注記で訊きます。
3. show.md の境目の行より前（pace.py が書いた部分）は、削りも書き換えもせず、既定の起動ではその全部を見せます。
4. `NEXT: show` のあとは、その起動の中ではプランを直しません（手順0は `NEXT: show` より前なので当たりません）。
5. `shown` は人間に見せたあとにだけ打ちます。既定の起動では、チャットに出した時点を「見せた」とします。
6. 束は必ず subagent に渡し、全部の結果が返ってから次の `next` を打ちます。答えのファイル（`*.out.json`）を自分で書いたり直したりしません。答えの無いジョブは、`next` が差し戻しの1回に数えます。
7. `verify` は叩きません（決定と gap ごとに1行を出し、長いプランでは千行になるので、この会話の文脈に入れないためです）。
8. pace.py の出力に出たファイル（`next` の `JOB`・`report` の `FILE fixes`・`show` の `FILE show`）のほかは、作業ディレクトリの中のファイルを開きません。
