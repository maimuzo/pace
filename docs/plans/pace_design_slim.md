# PACE の設計（要約版）

**この文書は要約版である。食い違ったら [pace_design.md](pace_design.md)（詳細版）が正である。**
人間のレビューを求めるたびに、詳細版から作り直す。手で差分を当てない。

## 何を作るか

**言いたいこと。**PACE は、AI が書いた設計プランから根拠のグラフを作る。根拠の無い決定・循環論法・プランに無い前提への依存を洗い出し、書き手（AI）が直すものと、人間が決めるものに分けて返す。continuo を知らない、単独の Claude Code プラグインとして配る。

- 入れ方: `claude plugin marketplace add maimuzo/pace` → `claude plugin install pace@pace`。更新は `claude plugin marketplace update pace` と `claude plugin update pace@pace`。マージ前に手元から試すときは `claude --plugin-dir <checkout>/plugins/pace`。
- 権限: `pace.py` は skill の `allowed-tools` で、起動したターンの間だけ確認なしで叩ける。subagent はバックグラウンドで動き、その完了の知らせで始まるターンには許可が続かないので、確認を出すモードでは利用者が settings に `Bash(python3 "<pace.py の絶対パス>" *)` と `Edit(**/.pace/**)` を足す（README に書く。途中を `*` にした規則で continuo の2本を分類と裁定まで、絶対パスの規則で89単位のプランの写しを根拠付けまで、確認なしで回せた）。
- 部品は4つ。
  - `pace.py`: 機械の仕事を受け持つ。AI は呼ばず、プランも書き換えない。
  - `SKILL.md`: 周を回す。
  - `pace-worker`（sonnet）と `pace-judge`（opus）: AI の仕事を受け持つ。
- 入力はプランファイル1本。根っこは、プランに書かれた前提である。

## 1回の起動で何が起きるか

```mermaid
sequenceDiagram
    participant M as 書き手（メインのセッション）
    participant S as pace.py
    participant H as 人間
    M->>S: init → next（束を subagent へ）… → report
    S-->>M: NEXT: continue（fixes 12件）
    M->>M: 確かめた事実と設計の変更だけを直す（最後に見せてから3周まで）
    S-->>M: NEXT: show
    M->>S: show
    S-->>M: show.md（質問・残った fixes・確かめられなかったもの・差分・照合していない旨）
    M->>H: show.md を見せる（--no-ask なら呼び出し側へ返す）
    M->>S: shown（見せた記録を進める）
    H-->>M: 回答
    M->>M: 回答を質問と組にしてプランへ書き、起動し直す
```

- `next` は、AI に頼むジョブ（分類 A/B・裁定）を束にして1回に4束まで出し、答えを検証して取り込む。答えが落ちたら3回まで差し戻し、使い切ったら失敗したジョブとして記録して先へ進む。答えはキャッシュに残し、指示文や agent の定義が変わったら作り直す。continuo の issue134（932単位）は33回の呼び出しで回った（1ジョブ1回なら208回）。
- ノードができたら、決定ごとに根拠の候補を規則で絞り（同じ H2・前後5単位・冒頭の節・識別子の共有、80ノードまで）、前提からどう導いたか（steps・claims・gaps）を AI に書かせる（r1）。AI が「候補に無いが探してほしい」と書いた内容は、文字の2-gram で近いノードを足して書き直させる（r2）。根拠付けのジョブは40,000字までで、subagent の Read の上限（25,000トークン）を測って決めた。束は120,000字までで、これは推論の値。continuo の issue224 は r1 が4束・r2 が3束で、確認なし・差し戻し0件で回った。
- 根拠付けのあと、決定どうしが互いを理由にし合う輪を探し、`pace-judge` に「本当の理由ではない辺」を切らせて、切られた決定だけ根拠付けし直す（輪を断つのは最大5回）。切った辺は「切られた側の決定の文」を鍵に残し、次の周からは最初から候補から外す。
- `verify` は、`DONE` まで進んだ作業ディレクトリを書き換えずに読み、決定ごとに根に届くか（rooted / needs_gap / ungrounded）・残った輪・gap ごとに止めている決定の数（効き）を出す。失敗したジョブに左右される決定は unverified として分け、fixes と questions に入れない。SKILL.md は `verify` を叩かない（出力が長く、見せ方は [#7](https://github.com/maimuzo/pace/issues/7) で決める）。
- 周を続けるか止めるかは、`pace.py` が決める。AI の申告には頼らない。
- 書き手がプランに足してよい文は、3種類だけ。確かめた事実（出どころ付き）・設計の変更・人間の回答（質問の文と原文の組）。価値や要求の理由は書かずに、人間に訊く。
- 秘密や個人の絶対パスは、プランにも注記にも書かない。
- 「人間に見せた」記録は、見せたあとに `shown` を打ったときだけ進む。見せていない書き足しは、次の起動の差分に出続ける。

## continuo と組むとき

- continuo の run は、計画を書いた直後・人間確認の前に、`/pace:pace --no-ask` を回す。
- 返された `show.md` は、人間確認の報告のコメントへ入れる。伏せる決まりは continuo の側が当てる。
- 回答のあとにもう一度回すかは、[#10](https://github.com/maimuzo/pace/issues/10) でオーナーに訊く。

## 防がないこと（限界の要点）

- 書き手が決まりを守ったか、事実の出どころが実在するかは、機械では確かめない。人間に見せる差分と注意で補う。
- plan mode の中では回らない。プランは plan mode の外で書き、PACE も plan mode の外で起動する（[#2](https://github.com/maimuzo/pace/issues/2) で手で頼んだとき、[#4](https://github.com/maimuzo/pace/issues/4) で skill から呼んだとき、どちらもプランを書いて止まった）。
- 判定役の `opus` が使えるかは、利用者の環境ごとに違い、確かめていない。環境変数・組織の設定・Claude Code の更新でモデルが変わっても、キャッシュの答えは作り直されない（そのときは `cache/` を空にする）。
- 束の結果が返る前に `next` を打つと、答えの無いジョブが差し戻しの1回に数えられる。束とジョブの大きさ・並列の数は仮の値で、[#9](https://github.com/maimuzo/pace/issues/9) で測り直す。長いプランでは、1回の起動で根拠付けの subagent を100回以上呼ぶ見込みで、まだ回していない。
- 根拠付けの候補を80ノードで切るときは遠い単位から落ちるので、大きな節では冒頭の節と識別子の共有の候補が先に落ちる。
- 冒頭の節か、H2 が1つしかないプランで分類のジョブが1件失敗すると、ほぼ全部の決定が unverified になり、その周の fixes はほぼ空になる（失敗したジョブは次の周で出し直される）。大きな輪を断つジョブの字数に上限は無い（[#9](https://github.com/maimuzo/pace/issues/9) で測る）。切った辺の記憶は、両端の文と、段の版・指示文・agent が同じ限り効き、節が違っても同じ文の決定は記憶を共有する。前の周に切った辺の記憶が消えると、その辺は黙って戻りうる。
- subagent の書き込みを許す規則（`Edit(**/.pace/**)`）は、プランが Claude Code を起動したディレクトリの下にあるときにしか当たらない見込み。メインのセッションの書き込みにも効くので、書き手が `*.out.json` を自分で書いても確認の画面では気づけない。
- 別の文書にある根拠は gap として出る。使ってみてから作り込むかを決める（[#9](https://github.com/maimuzo/pace/issues/9)）。
- 拡張子だけが違う2本のプラン（`plan.md` と `plan.txt`）は、作業ディレクトリが同じ `.pace/plan/` になるので、同時には回せない。拡張子だけを付け替えたプランも同じで、`init` は止まって知らせる。作業ディレクトリを消すと通るが、見せた記録も消える。
- 4つ字下げで書いたコードは、コードの1行ずつには分けない（フェンスで囲めば分ける）。英語のプランは1段落が1単位になる。
- `.pace/`（作業ディレクトリ）は、`init` を打った利用者だけが読み書きする。group で共有するプランを、複数の利用者で回す使い方はしない（ほかの利用者の `init` は書けずに止まる）。
- 箇条書きの記号を重ねた行（`- - ```go`）で開いたコードは、コードと見ず、そこから後ろの本文がコードの行として扱われる。記号を1行に1つだけ書けば避けられる。
- 誰が何を言ったか（発言者の扱い）は扱わない。扱う段は、回答の書き写し方とあわせて [#10](https://github.com/maimuzo/pace/issues/10) で決める。

| 9 | [#10](https://github.com/maimuzo/pace/issues/10) continuo の設計の流れで PACE を回すための issue を、continuo に起票できるようにする。なぜなら、計画を書いた直後・人間確認の前に、根拠の穴を見つけられるようにしたいからだ ／ 着手は、#9 の結果をオーナーが見て「動く」と判断してから |
